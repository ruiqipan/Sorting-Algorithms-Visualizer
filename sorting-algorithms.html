Overview

Sorting algorithms are fundamental building blocks in computer science. Understanding their trade-offs — time complexity, space usage, stability, and adaptivity — lets you pick the right tool for each problem. Click any card below to explore that algorithm in detail.

📐 Complexity Analysis

Best Case
O(n)
Already sorted — inner loop never executes, just one comparison per element.
Average Case
O(n²)
Each element compared with half the sorted portion: Σ(i/2) ≈ n²/4.
Worst Case
O(n²)
Reverse-sorted — every element shifts all the way to position 0: Σi = n(n−1)/2.
Space
O(1)
Only a temp variable for the key. Sorts in-place.

⚙️ How It Works

Think of sorting a hand of playing cards. You pick up one card at a time and slide it into the correct position among the cards you've already sorted.

1
Start from the second element. The first element is trivially "sorted."
2
Store the current element as key. Compare it with each element to its left.
3
Shift all elements larger than key one position right to open a gap.
4
Insert key into the gap. Move to the next unsorted element and repeat.

🎯 When To Use

✅Small arrays (n ≤ ~50) — low overhead beats faster algorithms.
✅Nearly sorted data — runs in near-linear time.
✅Online sorting — can sort elements as they arrive.
✅As a base case in Timsort and Introsort.
⛔Large random datasets — O(n²) is impractical.
⛔Adversarial data needing worst-case guarantees.
💡 Key Insight

Runtime is proportional to the number of inversions — pairs (i,j) where i<j but A[i]>A[j]. O(n) inversions → O(n) time. This is why Timsort uses insertion sort for small runs.

📐 Complexity Analysis

Best Case
O(n²)
Always scans the full unsorted portion — no early termination.
Average Case
O(n²)
Always n(n−1)/2 comparisons, regardless of input.
Worst Case
O(n²)
Same as best/average — comparison count is fixed.
Space
O(1)
Only a min-index variable and a temp. Fully in-place.

⚙️ How It Works

Repeatedly find the smallest element in the unsorted region and swap it with the first unsorted element.

1
Scan the unsorted portion to find the minimum.
2
Swap the minimum with the first unsorted element.
3
The sorted/unsorted boundary shifts right by one.
4
Repeat until sorted.

🎯 When To Use

✅When minimizing swaps is critical — at most n−1 swaps (e.g., flash memory).
✅Small arrays where simplicity matters.
⛔Nearly sorted data — can't adapt.
⛔Large datasets — always quadratic.
💡 Key Insight

Not adaptive — always the same comparison count. But performs at most n−1 swaps, optimal for swap count. Unstable because the long-range swap can reorder equal elements.

📐 Complexity Analysis

Best Case
O(n)
Already sorted — one pass, 0 swaps, early termination.
Average Case
O(n²)
~n/2 passes × ~n/2 comparisons each.
Worst Case
O(n²)
Reverse-sorted: every pair swapped, n(n−1)/2 total.
Space
O(1)
Only a temp for swapping. Fully in-place.

⚙️ How It Works

Walk through the array comparing adjacent pairs, swapping if out of order. The largest unsorted element "bubbles up" each pass.

1
Compare A[0] and A[1]. If A[0] > A[1], swap.
2
Continue for each adjacent pair through the array.
3
After one pass, the largest is at the end. Shrink unsorted region.
4
If no swaps in a pass, stop early — array is sorted.

🎯 When To Use

✅Detecting if data is already sorted — one O(n) pass.
✅Educational purposes — easy to understand.
⛔Any production use — insertion sort is strictly better.
⛔Large datasets — slowest O(n²) sort due to excessive swaps.
💡 Key Insight

Almost always inferior to insertion sort. Both are O(n) best, O(n²) worst, but insertion sort does fewer comparisons and moves on average. Bubble sort's main value is pedagogical.

📐 Complexity Analysis

Best Case
O(n log n)
Always splits and merges identically. Merge examines all n elements per level.
Average Case
O(n log n)
T(n) = 2T(n/2) + O(n). Master Theorem: Θ(n log n).
Worst Case
O(n log n)
Same recurrence regardless of input. log n levels × O(n) merge each.
Space
O(n)
Auxiliary array for merge step. Plus O(log n) recursion stack.

⚙️ How It Works

Divide-and-conquer. Split in half, sort recursively, merge the sorted halves in linear time.

1
Base case: 0 or 1 elements → already sorted.
2
Split at the midpoint into two halves.
3
Recursively sort left and right halves.
4
Merge: Two pointers compare fronts of both halves, always taking the smaller.

🎯 When To Use

✅Guaranteed O(n log n) worst case needed.
✅Stability required.
✅Sorting linked lists — O(1) extra space on lists.
✅External sorting — merging runs from disk.
⛔Memory-tight scenarios — O(n) auxiliary space.
⛔Cache-sensitive work — quicksort is more cache-friendly.
💡 Key Insight

Consistency is its strength and weakness — always ~n log n work, even on sorted data. The Master Theorem analysis T(n) = 2T(n/2) + Θ(n) → Θ(n log n) is the canonical example you've seen in class. The k-way variant (your homework!) gives the same asymptotic result.

📚 Master Theorem Walkthrough

From lecture, divide-and-conquer recurrences have the form T(n) = aT(n/b) + f(n) with f(n) = Θ(n^c). For merge sort we have a = 2, b = 2, and f(n) = Θ(n), so c = 1 and log_b a = log₂ 2 = 1.

The Master Theorem compares c and log_b a:

  • If c > log_b a, then T(n) = Θ(n^c) (the combine work dominates).
  • If c = log_b a, then T(n) = Θ(n^c log n).
  • If c < log_b a, then T(n) = Θ(n^{log_b a}) (subproblems dominate).

Since merge sort falls in the second case (c = log_b a = 1), we get T(n) = Θ(n log n): there are log₂ n levels of recursion and each level does Θ(n) total merge work.

Best Case Time
O(n log n)
Pivot always in the middle → balanced partitions.
Average Case Time
O(n log n)
Random pivots give balanced splits in expectation.
Worst Case Time
O(n²)
Pivot always min/max → (0, n−1) partitions. T(n) = T(n−1) + O(n).
Best Case Space
O(log n)
Balanced partitions → O(log n) recursion depth.
Average Case Space
O(log n)
Random pivots give balanced splits in expectation.
Worst Case Space
O(n)
Degenerate partitions → O(n) recursion depth.

⚙️ How It Works

Choose a pivot, partition so everything ≤ pivot is left and > pivot is right, then recurse on both sides.

1
Choose a pivot (random, last element, median-of-three).
2
Partition: Rearrange so ≤ pivot is left, > pivot is right. Pivot lands in final position.
3
Recurse on left sub-array.
4
Recurse on right sub-array.

🎯 When To Use

✅General-purpose — fastest comparison sort in practice.
✅Average case matters more than worst case.
✅Memory-constrained — O(log n) vs merge sort's O(n).
✅Randomized pivot makes worst case astronomically unlikely.
⛔O(n²) worst case is unacceptable (safety-critical).
⛔Stability required.
💡 Key Insight

Partition quality = performance. All-equal elements → (0, n−1) splits → O(n²) — exactly your homework Problem 3! Randomized quicksort gives expected O(n log n) for any input. Three-way partition handles duplicates by grouping equals together.

O(n log n)

Average Case
O(n log n)
n extract-max operations × O(log n) each.
Worst Case
O(n log n)
Guaranteed — no degenerate inputs possible.
Space
O(1)
Heap built within the array. Only constant extra.

⚙️ How It Works

Heap sort uses a max-heap: a binary tree stored in the array where each parent is greater than or equal to its children (index i has left child 2i+1 and right child 2i+2). The largest value always sits at the root (index 0). We first turn the array into a max-heap, then repeatedly take the root (the current maximum), swap it to the end of the unsorted region, and restore the heap by sift-down (compare the new root with its children and swap with the larger child until the heap property holds). The sorted part grows from right to left. Time is O(n log n) in all cases; space is O(1).

1
Build max-heap: Starting from the last non-leaf node, run sift-down at each node (compare with children, swap with the larger child if needed). This takes O(n) time total.
2
Extract max: The root holds the maximum. Swap it with the last element of the current heap so that maximum moves into its final sorted position.
3
Restore heap: The heap is one element smaller. Sift-down the new root (compare with left and right children, swap with the larger if needed; repeat until the node is larger than both children or has no children).
4
Repeat steps 2–3 until the heap has only one element. The array is then sorted.

🎯 When To Use

✅Need guaranteed O(n log n) AND O(1) space — unique combo.
✅Introsort fallback when quicksort recurses too deep.
✅Finding k largest/smallest — partial sort in O(n + k log n).
⛔General sorting — quicksort is faster in practice (cache).
⛔Stability needed.
⛔Nearly sorted data — not adaptive.
💡 Key Insight

Only comparison sort with O(n log n) worst case + O(1) space. But 2–3× slower than quicksort in practice due to cache misses from parent↔child jumps. Introsort uses quicksort primarily and only falls back to heapsort after O(log n) depth.

Same. For base-10: k=10, so each pass is O(n).

O(n + k)

⚙️ How It Works

Sort integers digit-by-digit from least significant to most significant, using a stable sub-sort for each digit.

1
Find d = number of digits in the largest number.
2
For each digit position (LSD to MSD):
3
Run stable counting sort on the current digit (base 10: k=10).
4
After d passes, the array is sorted.

🎯 When To Use

✅Fixed-width integers (32-bit, 64-bit).
✅d is small — 4 passes for 32-bit base-256 → effectively O(n).
✅Fixed-length strings (MSD variant).
⛔Floats without special bit handling.
⛔d·k large relative to n log n.
💡 Key Insight

Sub-sort must be stable — if the ones-digit sort disrupts tens-digit ordering, it breaks. For 32-bit base-256: d=4, k=256, total O(4(n+256)) — linear in n, beating all comparison sorts for fixed-width integers.

📐 Complexity Analysis

Best Case
O(n + k)
Perfectly distributed — each bucket has ~1 element, no sorting needed.
Average Case
O(n + k)
Uniform distribution with k=Θ(n): each bucket O(1) elements. Insertion sort on O(1) is O(1).
Worst Case
O(n²)
All elements in one bucket → degenerates to insertion sort's O(n²).
Space
O(n + k)
k buckets + n elements distributed across them + output.

⚙️ How It Works

Distribute elements into "buckets" by value range, sort each bucket (typically with insertion sort), then concatenate.

1
Create k empty buckets. Map each element to a bucket: bucket = floor(k × value / max).
2
Scatter: Place each element into its assigned bucket.
3
Sort each bucket individually (insertion sort works well for small buckets).
4
Gather: Concatenate all buckets in order.

🎯 When To Use

✅Uniformly distributed data over a known range.
✅Floats in [0, 1) — the classic textbook scenario.
✅k = Θ(n) buckets → expected O(n).
✅External memory sorting — distributing into buckets maps to disk.
⛔Skewed/clustered data — most elements in one bucket → O(n²).
⛔Unknown distribution.
⛔Space-limited — O(n+k) auxiliary.
💡 Key Insight

Performance depends on distribution uniformity. With k=n buckets and uniform data, expected bucket size is O(1), giving O(n) total. The worst case (all in one bucket) degenerates to insertion sort's O(n²). *Stability depends on using a stable sub-sort — insertion sort is stable, so bucket sort with insertion sort preserves stability.

🧠 Decision Guide: Which Sort?

1
Small array (n ≤ ~50)? → Insertion sort.
2
Nearly sorted? → Insertion sort. O(n + inversions).
3
Guaranteed O(n log n) + stable? → Merge sort.
4
Guaranteed O(n log n) + O(1) space? → Heap sort.
5
Fastest in practice? → Quicksort (randomized).
6
Integer keys, small range? → Counting sort. Many digits? → Radix sort.
7
Uniform distribution? → Bucket sort. Expected O(n).
8
Linked lists? → Merge sort. External (disk)? → External merge sort.

⚡ The Comparison-Based Lower Bound

Any comparison-based sort needs Ω(n log n) comparisons worst case. Proof: n! possible orderings → decision tree height ≥ log₂(n!) ≥ n log n. Merge sort, heap sort, and (expected) quicksort are asymptotically optimal among comparison sorts.

Counting sort, radix sort, and bucket sort bypass this by using key structure (integer values, distribution, digits) rather than comparisons alone.
